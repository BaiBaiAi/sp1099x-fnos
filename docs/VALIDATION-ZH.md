# r1 验证范围与尚未验证事项

日期：2026-10-27。

## 已完成

1. 开发设备：原生 fnOS 启动、真实重启、只读日志屏幕、真实电量/UPS 适配、有线管理、Wi-Fi 扫描/连接/自动重连、网页上传/下载/删除、指定 POSIX SMB 共享、Python FPK 和 Docker 的分项测试。Wi-Fi 仍有少量重复回包这一已知质量问题，不能称为长期稳定验收。
2. Windows 前端单元测试：英文/带空格路径允许；中文/非 ASCII 路径拒绝；GPT 头/分区数组 CRC 损坏拒绝；错误分区几何拒绝；远程 shell 参数转义；私有备份目录 ACL 设置。
3. GPT 稀疏磁盘往返测试：使用原厂几何将 37 分区变为原范围内的 8GiB 根分区 + 第 38 个数据分区，再恢复原厂 GPT；37 个原分区 UUID 保留。只测试文件，不写开发设备。
4. ARM 用户空间隔离测试：在独立挂载、网络、PID/IPC 命名空间中运行官方数据库及初始化/主服务，屏蔽主机块设备并限制能力。确认官方服务建立数据库结构后 `users=0`、`mount=0`；官方初始化能生成新 RSA 身份。未导出开发者的运行中数据库。
5. 新数据卷登记脚本：使用隔离数据库和模拟挂载，执行两次后 `users=0`、`mount=1`，验证其幂等性和未预置管理员。
6. 关键启动镜像/适配模块保持已验证的 #19 / 指定 SHA 版本；安装包从未初始化官方根文件系统和明确的适配允许列表构建。

最终包还应具有 SHA256.json、ZIP 外部 SHA-256、镜像/安装脚本静态检查和隐私检查结果；以本目录的最终构建记录为准。

## 不能据此声称的结果

- **全新 r1 自动安装器及 Fastboot 回退器没有第二台同款设备的完整实刷验收。** 本轮没有为了测试安装器而清空当前在用 NAS。
- 隔离 ARM 用户空间测试不能证明 MTK Recovery 冷启动、RNDIS 驱动、硬件写入、掉电恢复或每个批次电池/屏幕都正确。
- 不保证同名不同 DTBO/屏幕/存储批次；程序对此拒绝刷入。
- 不保证完整 TRIM/Windows ACL、官方 eBPF 安全监控、多日稳定、极限无线吞吐、休眠和无线功耗优化。
- 批次差异、未进入 Fastboot/Recovery的设备和 BROM/preloader 级别救砖，超出这个包的验证范围。

首台接收设备应先通过检查和备份，保留电脑日志，再实际验收首次设置、存储挂载、文件读写、应用安装、Docker、屏幕、重启和网络切换。验收后记录机型、DTBO 指纹、刷机日志及发现的问题，再决定是否扩大分发。
