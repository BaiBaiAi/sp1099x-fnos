SP1099X：从已 root 的 Android 安装原生飞牛 fnOS

文档版本：2026-10-27 / r1。对应本包，不适用于其他 MTK 平板。

1. 先确认适用范围

仅支持本次已验证的 SP1099X、MT6762V/CB / MT6765、4GB RAM、标称 32GB eMMC、Android 9（SDK 28）这一布局和设备树批次。工具会检查型号、平台、root、Bootloader 解锁状态、容量、全部 37 个原厂 GPT 分区以及 DTBO/原厂 Recovery 指纹。

同名设备可能使用不同屏幕、存储或板卡。检查不通过时停在检查结果，不要改脚本强刷，也不要借用其他机器的校准分区。包内没有强制忽略匹配的开关。64GB、不同屏幕/DTBO、不同分区表、第三方 Recovery 或其他 Android 版本均不在此候选包验收范围。

本说明从设备已经 root 开始。root 不等于 Bootloader 已解锁；本工具不会自动解锁，也不改写 preloader、lk、TEE 或校准分区。

2. 电脑、路径和连接准备

- Windows 10/11 64 位，使用本地磁盘，建议至少留出 15GB 空间容纳解压后的系统及目标设备备份。
- 平板电量至少 60%，使用可靠数据线直接连接电脑。安装期间维持连接，暂时不接平板的 OTG 网卡。
- 取出 TF 卡和其他外部存储，避免介质枚举或自动挂载造成混淆。
- 关闭手机助手、其他刷机软件和 ADB 调试任务。本工具会释放旧 ADB 服务器的 USB 句柄，使用包内 ADB 在端口 5038 启动独立服务。
- Windows 若尚不能识别 Android ADB，需要先在设备管理器正确绑定该设备的 Android ADB 驱动。能看到 `unauthorized` 时，先在平板上允许 USB 调试，不要重复安装 LibUSB。

将 ZIP 全部解压到例如：


D:\SP1099X-fnOS\
    SP1099X-Flasher.exe
    00-Verify.cmd
    01-Check.cmd
    02-Backup.cmd
    03-Install.cmd
    payload\
    tools\
    docs\
    source\


禁止放在 `D:\刷机\`、含中文用户名的桌面/下载目录等非 ASCII 路径。程序目录、当前工作目录以及手动指定的备份目录都会检查。NAS 文件名和 Wi-Fi 名称不受这项“电脑程序路径”限制。

程序从自己的 EXE 位置寻找全部工具和固件，不依赖系统 PATH 中的 adb，也不要求固定盘符。临时目录、ADB 用户目录和新生成的授权文件放在包内 `work/`，不依赖电脑用户配置目录。路径可以包含空格；命令行示例仍使用简单英文路径。

3. 检查包与设备

先双击 `00-Verify.cmd`。SHA-256 校验失败时重新获取完整包，不能进入刷写。

平板保持 Android 开机：

1. 开启开发者选项、USB 调试。
2. USB 数据线连接电脑，且仅连接这一台 Android 设备。
3. 运行 `01-Check.cmd`。
4. 平板出现 USB 调试授权时勾选信任这台电脑并允许。工具使用自己的新授权密钥，因此以前允许过其他工具也可能再次弹窗。
5. Magisk/su 弹出 shell 超级用户请求时允许。拒绝后应先在 root 管理器修正授权，再重新检查。

“检查通过”表示固件包、硬件、原厂分区几何和指纹符合本包范围，并未格式化或刷写设备。若输出 `Bootloader must already be unlocked`，先完成该设备既有解锁流程；本说明不包含解锁步骤。

4. 备份与安装

`02-Backup.cmd` 只备份、不刷写，可单独使用。准备立即安装时直接运行 `03-Install.cmd` 即可，因为安装本身会再创建一份完整备份。

右键 `03-Install.cmd` → 以管理员身份运行。管理员权限用于识别指定的 USB RNDIS 网卡、配置专用 USB 地址和临时传输防火墙规则，不会接管电脑自己的上网网卡。

程序显示设备序列号和清空说明，要求输入：


ERASE-屏幕上显示的完整设备序列号


不要照抄示例序列号。未输入匹配内容则退出。

工具先将目标设备的 GPT、原厂/当前 boot、Recovery、DTBO、系统、vendor、NVRAM/NVDATA、boot0/boot1 等分区保存到 `backups\日期-时间\`；除 cache 和 userdata 外的原厂分区均备份，并将分区内容与设备端 SHA-256 比对。备份失败或校验失败时不开始刷写。

备份不包含 userdata/cache。安装会销毁原 Android 用户数据、应用和加密数据密钥所依赖的数据内容。回退后的 Android 需要恢复出厂设置，旧用户数据不会回来。

备份完成后，程序将临时安装环境写到 Recovery 并启动它。安装环境使用本机原始分区备份，先恢复目标设备原厂 Recovery，再改变 userdata 范围；只有系统复制、数据卷创建和核验通过后，才最后写入主 boot。

安装使用：

- 原 userdata 起点不变；将其前 8GiB 用于 ext4 系统根目录。
- 在原 userdata 的剩余范围新增第 38 个分区，约 15.7GiB，创建本设备独立的 LVM + Btrfs 数据卷。
- 其他原厂分区的起点、大小和分区 UUID 保持不变。
- 新文件系统/LVM UUID、系统软件身份、维护 SSH 主机密钥均在目标设备生成。
- 无线私有校准文件从目标设备自己的 NVDATA 读取，绝不从开发机或其他机器复制。

此过程中设备屏幕可能没有内容，不能用背光判断进度；以电脑的安装阶段和日志为准。大文件下载或复制可能持续数分钟，阶段文字不变本身不代表卡住。

5. Windows RNDIS 处理

从 Android 切入安装环境后，ADB 暂时消失是正常的。电脑应出现一个新的 USB 网络设备。

安装器使用平板 `192.168.77.1`，电脑专用 USB 地址 `192.168.77.2`。本工具只针对主机端 MAC 为 `02-53-50-10-99-02` 的这一 USB 网卡工作，不按“以太网 2/3”等易变化名称选网卡，不配置默认网关，也不修改电脑上网网卡。

如果持续停留在等待 RNDIS：

1. 打开设备管理器，找到刚出现的 RNDIS/USB 网络设备。
2. 若 Windows 没有自动绑定驱动，使用“更新驱动程序 → 浏览我的电脑 → 从可用驱动列表选取”，选择 Microsoft 的“远程 NDIS 兼容设备”。仅对这个新增 USB 设备操作。
3. 保持数据线连接，回到刷机窗口等待。工具会继续检测，无需重新开始安装。

Windows 已有正确 RNDIS 驱动时无需手动操作。不要把电脑自己的 USB 以太网网卡改成 RNDIS，也不要为这个阶段随意替换成 LibUSB 驱动。

传输端口为电脑 TCP 18777，仅允许专用 USB 地址的平板访问；安装状态在平板 TCP 8080。工具退出时撤销自己新增的临时规则/地址，并在适用时恢复该 USB 接口原有 DHCP 模式。

6. 完成后首次进入 fnOS

看到 `complete` 后，电脑会保存安装日志，设备稍后自动重启。保持 USB 数据连接，等待系统首次启动，然后打开：


http://192.168.77.1:5666


首次页面创建你自己的超级管理员。包内没有预置 NAS 用户名、管理密码或默认 Wi-Fi 密码。账号密码仅在网页填写。

安装器已创建数据卷，首次服务会登记到 fnOS。预期存储空间为约 15.7GiB；系统根目录另占 8GiB，不能在存储管理中格式化系统或保留的原厂分区。若首次登记失败，先看后面的状态检查和日志，不要盲目重新分区。

首次可设置时区、时间同步和设备名。UPS/电池信息以及断电策略在系统设置中确认；低电压守护服务默认启用。不同充电/OTG 线的边充边用能力不一致，应观察真实电量变化，不能只依赖网卡灯判断供电。

每台设备的当前 NAS 地址由其网络实际分配，不会使用开发设备原来的 IP。

7. 包内维护、Wi-Fi 与状态检查

保留安装生成的那一份备份目录。以下命令均在解压目录的 PowerShell 中运行，将日期目录换成你自己的实际目录：


.\SP1099X-Flasher.exe --status ".\backups\20261027-123456"
.\SP1099X-Flasher.exe --wifi ".\backups\20261027-123456"


默认通过 USB 管理地址 `192.168.77.1:2222` 连接，使用此次安装独立生成的私钥和安装日志记录的设备 SSH 主机公钥进行双向身份校验。无需额外安装 SSH 客户端，也不使用开发者的密钥；主机身份不匹配时会拒绝连接。

`--wifi` 会扫描热点，询问 SSID 和密码。密码输入不回显，也不写入命令历史；连接配置保存在该设备 root 专用的 NetworkManager 文件中。此版本优先使用 WPA2，纯 WPA3 不在验收范围。

配置成功后输出 Wi-Fi IP；有线 DHCP 优先级高于 Wi-Fi。手机或电脑必须能够路由到对应网段，才能访问它的网页。离开 USB 管理连接前先记下新地址。

如果设备已改用有线/Wi-Fi 管理地址，例如 `192.168.1.50`，使用：


.\SP1099X-Flasher.exe --status ".\backups\20261027-123456" --host 192.168.1.50


平板接 OTG USB 网卡时，先完成上述网络准备，再拔电脑线、接 OTG 网卡与网线。AX88179 网卡已有开发设备实测；其他网卡及 TF/扩展坞组合需要单独验证。电脑自己的上网网卡保持原样。

8. 文件管理、私有 SMB 与 Docker

网页上传、下载、删除及回收站已有适配。权限采用 Linux 实际 UID/GID/POSIX 检查；不是完整实现 fnOS 私有 TRIM ACL 或 Windows ACL。

本包不复制开发机的 SMB 测试共享。创建管理员、登录网页并启用 SMB 后，可以用包内工具为该账号新建明确的私有 POSIX 共享：


.\SP1099X-Flasher.exe --share ".\backups\20261027-123456"


按提示填写你刚创建的飞牛账号，以及英文开头的共享名，例如 `NativeShare`。工具只在该用户 `/vol1/用户ID/` 下新建同名目录，只允许该账号访问，关闭这一个共享的 Windows ACL，保留其他共享配置。共享名已存在、用户不存在、SMB 用户尚未登记时会拒绝处理。

Windows 文件资源管理器访问 `\\NAS实际IP\NativeShare`，使用你自己的飞牛账号登录。共享中的普通文件名可以使用中文。

Docker 采用已适配的旧内核能力和 legacy iptables，数据目录设为 `/vol1/docker`，不复制开发者的容器、镜像或仓库凭据。32GB 设备的数据空间有限，镜像和应用会消耗这块约 15.7GiB 空间。

9. 安装失败与 Android 回退

任何 `failed` 都应保留完整 `backups`、`backup.json` 和 `install.log`。失败阶段不同，设备可能仍保留 Android boot，也可能已经改变 userdata 布局；不能一律再次运行安装，更不能使用别人的分区备份。

本包提供 Fastboot 回退入口。先让目标设备进入 Bootloader/Fastboot：仍可进 Android 时，可用包内 ADB 执行 reboot bootloader；Recovery 菜单若提供 Reboot to bootloader，也可使用。物理组合键因批次未在此安装器中验收，请按原厂进入方法操作。

以管理员身份打开解压目录的 PowerShell：


.\SP1099X-Flasher.exe --restore ".\backups\20261027-123456"


恢复过程再次要求输入 `ERASE-备份序列号`，核对 Fastboot 序列号，再临时从主 boot 启动 RAM 恢复环境。RAM 环境还会核对 eMMC CID 和所有备份哈希；不匹配的设备不会执行 GPT 恢复。

它恢复这台设备原来的 GPT 结构、boot、Recovery 和 para，并读取回校验；不改写校准分区，不把别人的硬件数据写入此机。GPT 原始恢复只覆盖头和分区表区域，不覆盖其他原厂分区内容。

看到 `restored` 后，进入原厂 Recovery，执行：

1. `Wipe data/factory reset`。
2. 确认 `Yes -- delete all user data`。
3. 完成后 `Reboot system now`。

这会清空剩余 NAS/Android 用户数据。回退不等于找回安装前的 Android 数据。 如果设备完全无法进入 Fastboot/Recovery，已超出本包恢复入口的验证范围，需要该设备原厂维修/MTK 恢复流程；本包不提供盲刷 preloader 操作。

10. 已知限制与分发规则

- 基础适配已实测，但此重新整理的安装器还没有第二台同款设备的完整刷入/回退实机验收。
- 屏幕是只读系统状态和日志显示，不是 fnOS 本地桌面，也未完成触摸交互适配。
- 无线可扫描、连接和自动重连。弱信号网络出现过重复回包；较强信号对照和关闭无消费者的固件详细日志后有改善，短测仍出现过少量重复包。不宣称多日稳定或已优化吞吐上限。
- 当前无线兼容路径保留 VCN28 供电并关闭无线省电，功耗/休眠优化尚未完成。
- 旧 4.9 内核不支持全部官方私有 ACL/eBPF 安全监控能力。不要把此候选包当作完整安全等价的官方受支持硬件。
- 系统/内核升级可能改变这些兼容接口。升级前保留原始分发包及本机备份，并核对适配版本。

给他人分发时，只转发原始 ZIP 和其 SHA-256。不要把运行后产生的 `backups/`、`work/`、维护私钥或设备 NVRAM 混进新的压缩包。

包内源码和第三方声明见 `source/`、`docs/THIRD-PARTY.md`。文件 SHA-256 用来检测损坏，并不是发布者数字签名。
